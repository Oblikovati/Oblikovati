# Legacy ADR migration map

Date: 2026-10-10. Status: application ADR migration complete.
All 66 legacy Go records have a disposition. They feed 13 new Rust application
records; no legacy acceptance or numbering is inherited.

## Source baseline

Every legacy link below names **Oblikovati** at commit
`aa8297d1b0ac33c024f19e54821536d76e8a447a`. The inventory is the 66 tracked
`architecture/decisions/ADR-*.md` files at that revision, not a directory count
from a changing checkout. Original records stay untouched in that repository.

The [port baseline](../rust-port/source-map.md) remains fixed. This migration
also inspected the following evidence; it does not silently update dependency
pins or claim new runtime test results.

## Reading the map

**Adapt and consolidate** retains only the sections described in the last
column, rewritten in the linked Rust records. **Reference only** keeps history,
counterexamples, and corpus inputs without making the old algorithm binding.
Its Rust link identifies the integration boundary that will use that evidence.
**Not applicable** omits a language-specific decision and names where its useful
intent remains covered.

When a row names several Rust records, the last column assigns each section
to its owner. A cross-reference does not create a second authority. Every
target record states context, the new decision, interfaces/invariants,
alternatives/consequences, legacy changes, and required implementation proof.

Accepted means the **Rust target design** was selected during this migration.
It does not mean a Rust feature, kernel extension, native binding, or release
passed acceptance. Runtime evidence is pending in the
[milestones](../rust-port/milestones.md) and
[verification plan](../rust-port/verification.md).

## Ownership handoff and remaining evidence

The application design migration is complete: 57 records have adapted content,
8 remain reference only, and 1 is not applicable as a language decision.
There are no unclassified legacy ADRs. This is not the R0 behavior inventory
and does not close R0 or any kernel capability gate.

[ADR-0007](ADR-0007-martensite-integration.md) owns application requirements at
the kernel interface. Algorithm choices, extension decisions, and corpus
ports belong to Martensite. Before implementing an extension, link its owning
kernel record and work item under K11. Its absence is an implementation
prerequisite, not permission to create an app-side kernel or drop the feature.

[ADR-0002](ADR-0002-api-and-addin-host.md) owns host conformance. API generation,
both language definitions, public type changes, and dual-language documentation
remain in Oblikovati.API. This migration does not replace either repository's
decision process.

The detailed Go Boolean/torus case histories remain available through their
fixed links. Read the relevant source, tests, later corrections, and oracle
evidence before adapting an algorithm. No wholesale algorithm correctness audit
or Rust runtime validation is claimed by this map.
