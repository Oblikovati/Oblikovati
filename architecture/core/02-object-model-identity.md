# Core 02 — Object model, types & identity

*Modernizes M00 (interop + RTTI). Implements ADR-0006. Cross-ref: identity/
reference keys live in [core/05](05-documents-persistence-identity.md).*

This is the most conceptually different layer from the COM original, so it gets
the most care. The COM object model overloaded one mechanism (`ObjectTypeEnum
Type` + variants + dual interfaces) to do **three** jobs. We split them cleanly.

## Job 1 — Behavior/dispatch → Go's static type system

In-process, there is **no RTTI**. A feature is a `*feature.Extrude`, a face is a
`*topo.Face`. Polymorphism is Go interfaces; heterogeneous handling is type
switches. The `kEdgeObject == obj.Type` integer compares of the COM world are gone.

```go
type Feature interface {
    Name() string
    Definition() Definition          // the recipe (the triangle, parametric-cad §3)
    SetDefinition(Definition) error  // round-trip edit → recompute
    Health() Health                  // ok|warning|sick|suppressed
    Recompute(ctx context.Context, in Inputs) (Result, error)
}
```

Selections (genuinely heterogeneous) are `[]Entity`, branched by type switch — see
ADR-0006. No `VARIANT`.

## Job 2 — Persistent/RPC identity → a stable `TypeID`

Saved files, reference keys, and the gRPC wire need a language-independent type
tag. We keep one — but **only at boundaries**, never for in-proc dispatch.

```go
// registry/types
type TypeID uint32   // STABLE FOREVER; never renumber (same rule as ObjectTypeEnum)

func Register[T any](id TypeID, codec Codec[T])   // at init()
```

- Every serializable type registers a stable `TypeID` + a codec at `init()`.
- These integers are immutable across versions (they live in user files). We
  reserve ranges per category, exactly as the original `ObjectTypeEnum` did — that
  discipline was correct and we keep it, just scoped to persistence.
- Go *type names* never appear in storage (they get refactored); only `TypeID`s do.

So: **static Go types drive behavior; immutable integer `TypeID`s drive storage.**
One COM enum's two jobs, now separated and each done well.

## Job 3 — Versioning → composition + protobuf

The `_X : X` dual-interface trick existed to add members without breaking the COM
ABI. In-proc Go has no ABI to preserve — we just add methods/fields. At the
**RPC seam**, versioning is protobuf's job (additive field numbers, never reused).
The 157 `*Definition` and 105 `*Enumerator` COM types collapse accordingly:

| COM surface | Here |
|---|---|
| `_Document : Document`, `_Feature : Feature` | one Go type per concept; methods added freely |
| 105 `*Enumerator` read-only views | `iter.Seq[T]` / `[]T` snapshots from queries |
| 275 `*Proxy` types | **one** generic proxy (entity + context), see below |

## Collections → generics

```go
type Collection[T Identifiable] struct{ ... }   // 0-based, range-able
func (c *Collection[T]) Add(T) ; Len() int ; At(i int) T ; ByID(ID) (T, bool)
```

Construction still happens **through the owning collection** (`features.Add(def)`),
because that is the seam enforcing history/identity/transactions (parametric-cad
skill §13) — that idea was right; only the `IEnumerable`/1-based packaging changes.

## The 275 proxies → one generic proxy

COM hand-generated a `*Proxy` per entity type to view part-space geometry in
assembly context. In Go it is **one parametric type** (the architectural win from
the parametric-cad skill §5a — "implement proxying once generically"):

```go
type Proxy[E Entity] struct {
    Native  E                 // the definition-space entity
    Context *OccurrenceContext// occurrence path + accumulated transform
}
func (p Proxy[E]) TypeID() TypeID { return p.Native.TypeID() } // same identity…
func (p Proxy[E]) Geometry() Geom { return p.Context.Apply(p.Native.Geometry()) } // …assembly-space geom
```

`Proxy[*topo.Face]`, `Proxy[*topo.Edge]`, `Proxy[*feature.WorkPoint]` — generated by
the type system, not by hand. The crucial property the skill demands is preserved:
**native ≠ proxy at the type level**, so part-space geometry cannot be silently
misused in assembly space.

## Entity identity (in-proc)

```go
type Entity interface {
    ID() ID            // stable within a document session (uint64), for selection/maps
    TypeID() TypeID    // stable across sessions, for storage/RPC
    BBox() math.AABB
}
```

- `ID` is a cheap session-stable handle for selection, maps, and the UI — *not*
  persisted (it is regenerated on load).
- **Topological** entities (faces/edges) additionally carry **reference keys** for
  cross-recompute/cross-session identity — the hard problem, in [core/05](05-documents-persistence-identity.md).

## The application session

`model.Workspace` replaces the `Documents` collection + `Application` document
ownership: it holds open documents, the active document, and the document
reference graph — reachable via the runtime mediator, not a global.

## Net effect

The entire **M00 interop milestone is deleted** (no managed/native marshaling).
What survives as "M00 work" is small and pure Go: the `TypeID` registry, generic
collections, the generic proxy, the entity interface, and `Workspace`.
